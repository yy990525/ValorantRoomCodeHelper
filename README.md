# 无畏契约抢码助手 0.3

Windows x64 桌面助手：内嵌抖音网页，隐藏网页弹幕、聊天和装饰，只识别视频中的三个大写英文字母加三个数字。支持自动复制，以及向已经打开的游戏房间码输入框发送粘贴。

## v0.3 界面更新

- 使用新生成的“房间码卡片与扫描框”图标；EXE、窗口标题栏、任务栏与托盘共用图标。
- 点击暂停或按 F8 暂停后，自动恢复原网页，显示网页弹幕、聊天和装饰。最新码与识别预览保留，预览标明暂停前最后一帧。
- 点击右上角“切换浅色 / 切换深色”即时切换主题，选择会保存；不会启动识别或切换网页。
- 标题栏、按钮、输入框、设置下拉菜单与细圆角滚动条跟随主题。标题栏支持拖动、双击最大化 / 还原，以及最小化、最大化、关闭。
- 设置页重新调整间距，修正选项与背景颜色，避免原有浅底白字问题。

新版放在独立目录。若需要沿用旧版登录状态与设置，关闭旧版后，将旧版 `Data/` 文件夹复制到新版 EXE 所在目录。

## 开始使用

1. 完整解压，在可写文件夹中运行 `ValorantRoomCodeHelper.exe`。EXE、模型和 DLL 需要一起保留。
2. 打开抖音直播链接，完成必要的网页登录，并播放直播。
3. 默认开启“全画面自动识别”，直接点击“开始识别”或 F8，无需框选。软件先检查浏览器、OCR、视频播放、截图和识别范围，通过后开始连续识别。
4. 点击开始不会进入全屏，也不会自动放大视频。隐藏网页弹幕、聊天后，视频保留原有位置和显示尺寸，地址栏仍然显示。“全画面”指 OCR 读取整个视频，与播放器全屏无关。
5. “识别自检与预览”显示真正送入 OCR 的画面、区域尺寸及取帧时间。点击“自检”可暂停识别并单独检查。
6. 如果视频出现多个符合格式的码，会阻止自动复制与填入。可点击“框选识别区域”，只框住房间码，保存后自动切换到框选模式。Esc 取消。再次启用全画面模式可恢复整个视频识别。
7. 默认连续两帧确认，再自动复制。F9 或“再次复制”可重新复制最新码。次要开关收在“更多设置”中。

## 自动填入游戏

1. 在无畏契约中打开“加入房间”的房间码输入框，保持这个界面打开。
2. 在助手中点击“绑定游戏输入框”。有 6 秒准备时间：切换到游戏，把鼠标放在房间码输入框内部，停留等待绑定完成。
3. 返回助手确认出现“已绑定输入位置”，开启“识别后自动填入游戏”，开始识别。
4. 新码通过连续确认并复制成功后，助手会尝试切换到已绑定的游戏窗口，点击绑定位置，发送 Ctrl+A、Ctrl+V。它不会发送回车或点击加入按钮；请在游戏检查码并自行确认加入。
5. “填入最新码”可以手动重试，并会暂停识别。再次复制或双击历史记录只执行复制。

开启自动填入会同时开启自动复制、关闭助手置顶，避免助手遮住游戏。绑定只在本次运行内有效；重启软件、重启游戏或改变游戏窗口尺寸后需要重新绑定。移动窗口会按游戏客户区坐标换算新的屏幕位置。

绑定确认的是游戏窗口和你指定的坐标，不能判断游戏菜单是否仍停留在房间码输入框。切换菜单后请重新打开加入窗口并绑定。目标进程目前匹配 `VALORANT-Win64-Shipping`；若客户端无法绑定，需要针对实际客户端适配。

每一步输入前会检查绑定窗口、进程身份、窗口尺寸、焦点、按键状态和剪贴板。检查失败保留已复制的码并提示原因，不自动重试填入。暂停或关闭自动填入会取消尚未发送的后续操作。

“已发送填入”表示系统收到模拟输入请求，不能确认游戏已经接受。客户端、权限或输入限制可能导致粘贴无效，需在你的游戏中试用。建议先用游戏窗口化或无边框模式，助手保持打开且不最小化。真实游戏的粘贴与加入效果尚未验证。

## 试用与识别规则

“本地试用”打开动态演示视频，每 18 秒换码，无需登录抖音。正常试用会按自动复制设置写入剪贴板，但演示码不会发送到真实游戏。

- 格式严格为 `AAA000`，不把小写转大写，不猜测 O/0 或 I/1。
- 低得分、多候选和没有结果时不发布。全视频模式可能识别到其他符合格式的文字；需要精确指定来源时使用框选模式。
- 同一码持续出现不会重复复制或填入。不同码更新结果，最近见过的码受冷却时间限制。
- 自检没有发现码仍可通过：它检查识别链路是否可用，开始后等待房间码出现。自检通过不代表 OCR 准确率或房间码有效性。
- 只识别视频，不读取网页聊天。网页叠加弹幕可隐藏；主播合成到视频像素中的文字、摄像头和图层会保留。
- 网页切换、视频暂停、播放器替换和截图异常会暂停识别。窗口隐藏或最小化时暂缓取帧；被其他窗口遮挡时的更新效果需在实际设备上验证。

## 设置与数据

F8 开始/暂停、F9 复制最新码，可改为 F6–F12。支持采样间隔、得分阈值、冷却时间、历史数量、提示音、托盘、置顶和日志导出。

`Data/` 在 EXE 同一目录，保存设置、按直播间记住的框选区域、历史及独立浏览器资料（包括登录状态）。截图不自动长期保存。识别在本地 CPU 完成，不上传截图。退出后删除自己的 `Data/` 可恢复初始状态。

发行包包含 .NET 运行时、OCR 模型和应用本地 C++ DLL，仍需 Microsoft Edge WebView2 Runtime。微软下载页：https://developer.microsoft.com/microsoft-edge/webview2/#download-section

当前接入主页面 HTML `video`。抖音页面变化、验证要求或其他播放器方式可能需要适配。直播延迟、压缩、字体和清晰度都会影响识别；格式合格不能证明房间存在或有空位。

## 编译与验证

技术栈：.NET 10 LTS、WPF、WebView2、RapidOcrNet 4.2.0、PaddleOCR v5 Latin ONNX、ONNX Runtime 1.29.0。自动填入使用 Windows 用户态窗口与输入 API。

安装 .NET 10 SDK 后运行：

```powershell
.\build.ps1 -Action Restore
.\build.ps1 -Action Test
.\build.ps1 -Action Publish
```

支持 `-SdkPath`、`-CachePath`、`-FeedPath`、`-OutputPath`。核心测试共 36 项，包括识别与自动填入中断场景。

`ValorantRoomCodeHelper.exe --smoke-test` 使用独立 `TestData/`、内存剪贴板和模拟游戏输入，不向真实游戏发送输入。验证真实 HTML 视频、纯画面布局、原尺寸保留、不自动全屏、动态浮层隐藏、全视频 OCR、自检、预览、去重、填入流程、暂停自动恢复聊天、框选范围缩放，以及深浅主题、标题栏、图标与控件实际文字对比度。报告位于 `TestData/smoke-passed.txt` 或 `smoke-failed.txt`。

`ValorantRoomCodeHelper.exe --douyin-check` 使用独立 `LiveCheckData/` 检查公开抖音播放、纯画面取帧、全视频自检和暂停恢复网页。不使用用户登录状态，不验证具体游戏直播间或真实游戏自动填入。

`Core/` 包含识别规则、区域映射、设置及填入流程；`App/` 包含界面、播放器、OCR、原生输入、快捷键及托盘；`Tests/` 包含行为测试。第三方依赖参见 `THIRD-PARTY-NOTICES.txt`。

程序图标由内置 imagegen 工具生成，项目资源位于 `App/Assets/app.png` 与 `app.ico`。ICO 包含 16、20、24、32、40、48、64、128、256 像素尺寸。
